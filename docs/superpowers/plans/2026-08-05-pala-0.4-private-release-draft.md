## Mimari ve Arayüzler

- `SessionState`, `TicketState`, `Ownership`, `LifecycleState` ve
  yapılandırılmış `VerificationRecord` modelleri ayrılacak. Ticket durumları
  `active`, `checkpointed`, `blocked`, `completed`; aynı ticket'ın eşzamanlı
  tek sahibi olacak.
- Dinamik schema v3 durumu `.codex/plugin-data/pala/v3/` altında session ve
  ticket başına atomik JSON olarak tutulacak. Session anahtarı
  `SHA-256(session_id)` özetinden üretilecek; transcript ve ham session kimliği
  saklanmayacak. Ticket mutasyonları atomik kilit ve geçici dosya + replace
  düzeni kullanacak.
- Schema v2 çalışma durumu ilk kullanımda kayıpsız içe aktarılacak; eski dosya
  silinmeyecek. Farklı session'lar farklı ticket'larda paralel çalışabilecek;
  dirty ticket sessizce devralınamayacak.
- `pala_state.py` mevcut komutları uyumlu tutacak ve `--session-key`
  desteğiyle `resume`, `record-verification`, `recover` ve `complete`
  komutlarını ekleyecek. `checkpoint` sahipliği bırakacak; `complete`
  blockersız ve geçmiş başarısızlığı kapatan uygun doğrulama kanıtı isteyecek.
- Aynı nedensel doğrulama hatası en fazla iki otomatik yeniden deneme alacak;
  üçüncü sonuç blocker olacak. `failed`, `timeout`, `blocked` ve `not-run`
  hiçbir koşulda başarı sayılmayacak.
- Ortak adaptör yüzeyi:
  - `IMCP.inspect/ensure(McpSpec, dry_run)`
  - `IGraph.inspect/analyze(root, action)`
  - `ITool.inspect/install/doctor(dry_run)`
  - Ortak sonuç: `AdapterResult(name, state, changed, detail, evidence)`;
    durumlar `ready`, `missing`, `external_conflict`, `unsupported`, `failed`.
- GitHub ayrı `GitHubRouter` olarak connector → `gh` → salt-okunur Git
  sırasını izleyecek; token veya yeni API istemcisi paketlemeyecek. Yazma
  yetkisi işlem bazında korunacak.

## Test ve Release Kapıları

- State testleri: iki session/aynı ticket çakışması, farklı ticket paralelliği,
  idempotent claim, dirty takeover reddi, temiz resume, stale recovery audit
  izi, lock contention, yarım yazma, schema göçü ve bounded hook context.
- Adaptör testleri: ready/missing/conflict/unsupported durumları, dry-run sıfır
  yazma, kullanıcı ayarı koruma, pin/integrity doğrulama ve bağımlılık
  eksikliği.
- RTK testleri: gerçek `v0.44.2` binary ile allowlist, argüman/çıkış kodu
  eşdeğerliği, compound/mutating/secret passthrough, RTK-yok fallback ve bütün
  `tool_input` alanlarının korunması.
- Dayanıklılık testleri: 50 ardışık install/doctor/update; güncel, eski, bozuk,
  yabancı, kilitli, offline, eksik PATH/Python/Node/uv, rollback, repair ve
  uninstall.
- Yerel milestone kapısı: `py -3 scripts/verify.py`, sistem skill/plugin
  doğrulayıcıları, source ve portable ZIP doğrulaması, secret taraması ve temiz
  Windows PowerShell 5.1/7 profil kurulumu.
- GitHub teslimi: `codex/pala-0.4` push → private PR → Windows/Ubuntu CI →
  merge commit → main CI. Başarıdan sonra manifest
  `0.4.0+codex.<cachebuster>`, tag `v0.4.0`, portable ZIP ve checksums içeren
  private release oluşturulacak.
- Release sonrası authenticated private checkout/ZIP üzerinden temiz kurulum,
  doctor ve yeni Codex task'ında açık/örtük Pala çağrısı doğrulanacak.
