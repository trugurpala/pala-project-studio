# Pala 0.4 Session and Safe Adapters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans`
> to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver Pala 0.4 with concurrent session-safe ticket ownership,
managed safe adapters, and a verified private release while preserving existing
project state and user-owned configuration.

**Architecture:** Keep `pala_state.py` as the compatibility CLI facade, move
state records and atomic storage into focused standard-library Python modules,
and add protocol-backed adapters for MCP, Graph, managed tools, and GitHub
routing. Optional integrations degrade honestly; the clean-profile release
path proves their pinned installation.

**Tech Stack:** Python 3.12 standard library, PowerShell 5.1/7, Codex CLI,
`uv`, RTK 0.44.2, code-review-graph 2.3.7, unittest, GitHub Actions.

## Global Constraints

- Preserve the schema v2 `discover`, `begin`, `checkpoint`, `context`, and
  `doctor` CLI behavior; new session behavior is opt-in through `--session-key`.
- Store v3 dynamic state only below ignored `.codex/plugin-data/pala/v3/` and
  never persist transcripts, raw session ids, tokens, or credentials.
- Do not alter foreign MCP, plugin, GitHub, or user tool configuration.
- Core Pala remains usable offline and without optional adapters.
- RTK rewrites only simple, allowlisted read-only Bash commands; all uncertain
  commands retain their exact original input.
- Do not create a public release or change repository visibility.

### Task 1: Session-safe workflow storage

**Files:**
- Create: `scripts/pala_models.py`, `scripts/pala_store.py`
- Modify: `scripts/pala_state.py`, `scripts/test_pala_tools.py`

**Interfaces:**
- `SessionKey.from_session_id(value: str) -> str` returns the first 24 hex
  characters of SHA-256; raw ids never enter stored JSON.
- `TicketRecord(ticket, goal, lifecycle, owner, dirty, next_action,
  verification, blockers, checkpoint_basis, updated_at)` serializes only
  bounded, secrets-free values.
- `WorkflowStore.claim`, `checkpoint`, `record_verification`, `complete`, and
  `recover` lock one ticket directory, atomically replace its JSON record, and
  return a typed result.

  different tickets, idempotent same-session claim, clean checkpoint/reclaim,
  dirty takeover refusal, stale recovery audit, and v2 migration preservation.
- [ ] Run the new tests and observe failure because v3 models and storage do
  not yet exist.
- [ ] Implement the immutable models, ticket-scoped lock directory, atomic
  write/replace operation, bounded record validation, and non-destructive v2
  import marker.
- [ ] Extend `begin`, `checkpoint`, `context`, and `doctor` with optional
